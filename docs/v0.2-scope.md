# lokiotel v0.2 — review fixes + extensibility refactor

This document is the authoritative scope for the v0.2 work. Read SPEC.md
alongside this.

## Design principles (hard rules — apply throughout)

1. **SRP**: one reason to change per file/type. If a type knows about both
   config schema AND process supervision AND OTLP wire format, split it.
2. **DRY**: any logic used in more than one spot must live in one place.
   Duplicated tmp-file-rename persistence, repeated anonymous sink
   interfaces, and scattered helpers all must be fixed.
3. **Extensibility**: adding a new collection mode ("claude-code",
   "goose", "cursor", …) must be **strictly additive**. A contributor must
   be able to drop a new package under `internal/<mode>/`, register it,
   and not edit any other file (except `cmd/lokiotel` imports). Concretely:
   - No switch statements on mode outside the registry.
   - No references to "openclaw" in `cmd/`, `internal/config`, `internal/otlp`,
     `internal/systemd`, `internal/status`.
   - Each collector package owns and validates its own config sub-struct.
4. **Testability**: anything non-trivial gets a table-driven test. No
   "untestable" logic allowed.
5. **Multi-OS**: Linux (Amazon Linux 2023 + Ubuntu 22/24) first class;
   macOS supported for `start` + `status --local` at minimum; Windows
   explicitly out of scope.

## Blockers to fix (from review)

### B1 — install fails on a clean host
`config.Load()` validates `openclaw.session_dir` before `install` has a
chance to write a config file. Fix:
- Add `--session-dir` install flag.
- On each supported OS, default `session_dir` to a sensible path
  (`$HOME/.openclaw/agents/main/sessions`, falling back to
  `/home/<user>/.openclaw/agents/main/sessions` when run as root via sudo).
- Split validation into two phases: `ValidateBootstrap()` (endpoint + mode +
  token only) for install-time, and full per-collector `Validate()` for
  runtime. `install` calls only the bootstrap phase.

### B2 — service will crash reading its token
Install writes token file and state dir as root, but service runs as
`User=lokiotel`. Fix:
- After `ensureUser()`, look up the uid/gid.
- `os.Chown` `/etc/lokiotel/token` to `lokiotel:lokiotel` with mode 0400.
- `os.Chown` `/var/lib/lokiotel/` (and everything inside) to
  `lokiotel:lokiotel` recursively.
- Add a systemd-package test that asserts we call chown with the right
  arguments (use an interface around filesystem ops so the test can inject
  a fake).

### B3 — plaintext HTTP endpoint accepted silently
- `Config.Validate()` must reject any endpoint not starting with `https://`
  unless `--insecure-endpoint` / `insecure_endpoint: true` is set in config.
- Add a negative test.
- README must call out the flag and when (if ever) to use it.

### B4 — pack.agent.turn under-counted
- Remove the `LastTopRole` suppression for assistant messages. Every
  assistant message in the transcript emits one `pack.agent.turn`.
- Keep (or add) deduplication against the persistent offset so we don't
  double-count on rescan.
- Add a regression test with back-to-back assistant messages (tool-use
  cycles) and assert the counter equals the message count.

## Extensibility refactor (the big one)

### Remove openclaw-specific types from the top-level Config

Replace:

```go
type Config struct {
    Mode      string         `mapstructure:"mode"`
    ...
    OpenClaw  OpenClawConfig `mapstructure:"openclaw"`
    Declared  DeclaredConfig `mapstructure:"declared"`
}
```

with a generic form that stores each collector's sub-config as a
deferred, type-erased value:

```go
type Config struct {
    Mode              string            `mapstructure:"mode"`
    Endpoint          string            `mapstructure:"endpoint"`
    TokenFile         string            `mapstructure:"token_file"`
    LogLevel          string            `mapstructure:"log_level"`
    InsecureEndpoint  bool              `mapstructure:"insecure_endpoint"`
    Declared          DeclaredConfig    `mapstructure:"declared"`

    // Raw collector sub-config, decoded later by the selected collector.
    // Keyed by mode name. The top-level config package does NOT know any
    // collector's schema.
    Collectors        map[string]any    `mapstructure:",remain"`
    // or equivalent: store the raw viper sub-tree.
}
```

Each collector decodes its own subsection from `Collectors[Name]` via a
`CollectorConfigDecoder` function passed at registration time.

### Self-registering collectors

`internal/collectorapi/api.go` gains:

```go
type Spec struct {
    Name        string
    Description string
    Factory     func(rawConfig any, store *status.Store, base config.Config) (Collector, error)
    DecodeFn    func(raw any) (validated any, err error)  // optional
    DefaultConfig func() any                              // optional
}

var registry = map[string]Spec{}

func Register(s Spec)  // panics on duplicate name
func Lookup(name string) (Spec, bool)
func All() []Spec
```

Each collector registers itself via `init()`:

```go
// internal/openclaw/register.go
func init() {
    collectorapi.Register(collectorapi.Spec{
        Name:        "openclaw",
        Description: "OpenClaw agent session tailer",
        Factory:     newOpenclawCollector,
        DecodeFn:    decodeOpenclawConfig,
        DefaultConfig: defaultOpenclawConfig,
    })
}
```

`cmd/lokiotel/main.go` adds a blank import:

```go
import (
    _ "github.com/inceptionstack/loki-otl/internal/openclaw"
)
```

Adding a new mode means:
1. Create `internal/claude_code/` package
2. Implement `Collector`
3. Register it in `init()`
4. Add `_ "…/internal/claude_code"` to `cmd/lokiotel/main.go`

Nothing else.

### Remove mode-specific references everywhere else

Grep the tree for "OpenClaw" / "openclaw" (case-insensitive) after the
refactor. The ONLY files that should match are:
- `internal/openclaw/**`
- The one blank import in `cmd/lokiotel/main.go`
- README.md where we document the v1 mode
- SPEC.md (unchanged)

Specifically fix:
- `internal/otlp/sink.go` — don't hardcode `mode="openclaw"` in the flush
  log; take mode as a constructor arg.
- `cmd/lokiotel/status.go` — mode-specific status lines come from the
  collector via a `StatusReporter` interface, not from reaching into
  `cfg.OpenClaw.*`.
- `cmd/lokiotel/start.go` — use the generic collector factory.

### StatusReporter interface for `lokiotel status`

```go
type StatusReporter interface {
    Collector
    ReportStatus(ctx context.Context) []StatusLine
}

type StatusLine struct{ Label, Value string }
```

`status.go` prints the generic lines (unit, mode, endpoint, last flush,
last heartbeat, dropped batches) then iterates collector-specific lines.

## Multi-OS support

### Build-tagged service layer

Split `internal/systemd/` into a platform-agnostic interface package
`internal/service/` with build-tagged implementations:

```
internal/service/
  service.go         // interface + common types (no build tag)
  service_linux.go   //go:build linux  — systemd implementation
  service_darwin.go  //go:build darwin — launchd (minimal: just return
                      //                 ErrUnsupported for install/uninstall,
                      //                 probe for process status)
  service_other.go   //go:build !linux && !darwin — unsupported
```

Interface:

```go
type Service interface {
    Install(cfg config.Config, token string) error
    Uninstall() error
    EnableAndStart() error
    ProbeStatus() (Status, error)
}

type Status struct {
    Installed bool
    Active    bool
    Detail    string // e.g. "active (running) since …" or "not installed"
}

var ErrUnsupported = errors.New("platform does not support daemon install")
```

`cmd/lokiotel/install.go` on Darwin prints:

```
lokiotel install is not supported on macOS.
You can still run `lokiotel start --config /path/to/config.yaml`
directly or under launchd. See docs/macos.md.
```

And exits non-zero.

### Linux distro handling

- `ensureUser()` in `service_linux.go` must work on Amazon Linux 2023,
  Ubuntu 22/24, Debian, and RHEL-likes.
- Use `getent passwd lokiotel` to probe first.
- Prefer `useradd --system --home-dir /var/lib/lokiotel --shell /usr/sbin/nologin lokiotel`.
  Fall back to `/sbin/nologin`, then `/bin/false`.
- On a system without `useradd` but with `adduser` (rare on server distros),
  fail cleanly with a clear error.

### macOS start path

`lokiotel start --config foo.yaml` must work on macOS with default
config paths adjusted:
- Config default: `$HOME/.config/lokiotel/config.yaml`
- State default:  `$HOME/.local/share/lokiotel/`
- Status default: `$HOME/.local/share/lokiotel/status.json`

Implement `config.DefaultPaths(platform string)` returning a struct with
all the path defaults, and use it in `config.Load()` based on `runtime.GOOS`.

## DRY / SRP cleanup

### Atomic file writes
Extract `internal/fsatomic/write.go`:
```go
// WriteFile writes data atomically to path, 0o644 by default, using
// tmp-file-and-rename. Permissions and owner are optional.
func WriteFile(path string, data []byte, opts ...Option) error
```

Replace usage in `internal/openclaw/state.go` and `internal/status/store.go`.

### Small helpers
Move `asString`, `firstText`, and similar generic helpers from
`internal/openclaw/collector.go` to `internal/jsonx/` (a clearer home).

Move `seriesKey` and related buffer bookkeeping to its own file
`internal/otlp/series.go` and add a unit test.

Delete `errorsIsEOF` — it's `err == nil || errors.Is(err, io.EOF)`, inline
it and drop the helper.

### Collector anonymous interfaces
Remove the repeated `interface { Counter(...) }` on collector functions.
Either pass `collectorapi.MetricSink` through, or define a local named
type once. Every collector function must take a concrete, documented sink
type.

### `ToYAML()` via yaml.v3
Replace the `fmt.Sprintf` hand-roll with:
```go
func (c Config) Marshal() ([]byte, error) {
    return yaml.Marshal(c)
}
```
(And add yaml struct tags on Config.) Add a round-trip test that
marshals + unmarshals Config and asserts equality.

## Test coverage additions (required for merge)

1. **collector end-to-end** (`internal/openclaw/collector_test.go`):
   - Write a fake JSONL file in a tmpdir.
   - Run one `scan()` against a fake `MetricSink`.
   - Assert exactly the expected counter emissions.
   - Include: session start, 3 assistant messages (all 3 counted), 2
     tool calls (tool.class derived correctly), 1 error.
   - Append a partial line, rescan, assert no re-read / no double count.
   - Append completion bytes, rescan, assert the line is processed exactly
     once.
2. **sink failure paths** (`internal/otlp/sink_test.go`):
   - Success path: 2 points, 200 OK, DroppedTotal=0.
   - 401: AuthFailure=true, DroppedTotal=1.
   - 500: Dropped=true, AuthFailure=false, DroppedTotal=1.
   - transport error: status 0 logged, DroppedTotal=1.
3. **config negatives** (`internal/config/config_test.go`):
   - unknown mode → error.
   - missing endpoint → error.
   - `http://…` endpoint without `insecure_endpoint: true` → error.
   - unknown openclaw sub-key → error (after the refactor, this is
     enforced by the collector's decoder).
4. **service layer tests** (`internal/service/service_linux_test.go`):
   - `renderUnit()` contains the exact required `User=`, `ExecStart=`,
     `ReadWritePaths=`, `ProtectSystem=strict` lines.
   - `install()` chowns both token and state dir — use an fs abstraction
     so the test can run without being root.
5. **registry invariants** (`internal/collectorapi/registry_test.go`):
   - `Register` panics on duplicate name.
   - `All()` returns sorted deterministic list.
   - `Lookup("missing")` returns `ok=false`.

## CLI polish

- `lokiotel install --help` must show EVERY flag with its env var and
  config-file key, like `aws` does.
- `lokiotel install` prints unit status at the end (required by SPEC but
  missing).
- `lokiotel status` returns non-zero when the unit is not active.
- `lokiotel version` prints commit + date + GOOS/GOARCH, injected via
  ldflags in the Makefile.
